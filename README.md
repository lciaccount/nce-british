# NCE · 原声英语

独立的新概念英语学习网页，交互参考 `french-2000`，使用用户提供的 `/home/lc/nce/英音` 原始 MP3 与英文 LRC。**先做英文与原声，以完整句子为学习单位，不包含中文翻译。** 原法语项目与原始素材没有修改。

## 内容与时间轴

- 第 1 册 72 个音频课（奇数课课文，对应原文件的成对课号），第 2 册 96 课，第 3 册 60 课，第 4 册 48 课，共 **276 课**。
- 本次生成 **4,670 个完整句子**，其中 **63 句**自动对齐分数偏低，已标注待复核；学习单位不是原 LRC 的字幕行。
- 原始录音共约 **551.5 MiB**，保持原文件字节，不做 TTS 替换，也不伪造三种音色。
- 自动处理 UTF-8 / GB18030 字幕，去除软件广告和空字幕；学习句子排除课号、标题和听录音指令，保留课前问题及正文。
- NLTK 英文断句合并跨行句子，并拆分同一字幕行中的多句话；使用本机 Wav2Vec2 CTC 声学对齐重新定位起止时间。播放的是原录音对应区间，没有按字符长度估算切点。
- `import-report.json` 保留原字幕检查结果：原 LRC 有 47 课出现越界时间戳。因此不能把原字幕时间直接当作句子时间。`alignment/` 保存新的逐句时间、分数和原音频 SHA-256；`alignment-review.json` 列出低置信度结果。
- 自动对齐不等于人工听校，专名、数字、源字幕拼写问题可能影响精度。页面明确标注待复核句子，并提供本地时间校准。
- 素材目录标注“英音”，但部分 LRC 元信息写“美音”；本项目按用户提供的录音制作，没有逐课认证口音。

## 功能

- 按册、课选学，搜索课名或英文正文，收藏和掌握标记，记住最后学习位置。
- 册数采用紧凑按钮；选课列表默认折叠，展开可选课，选完自动收起，搜索／收藏筛选自动展开结果。
- 单句循环、逐句播放、整课播放及高亮、播放间隔、**0.50×–2.00×（步长 0.05）**。
- 主界面固定播放底栏也提供倍速选择，与课文上方和大屏模式实时同步，刷新后保留；切换倍速不会重播当前句。
- 大屏滑动模式：上下滑动切句，默认循环当前句；可设置课内句子区间、每句次数、自动切换及区间末尾循环。
- 防误触锁定，英文原文隐藏／揭示，上下文展开，80%–160% 字号，首次进入 1.5 秒手势提示。
- 按课编号区间下载原声音频，显示体积与进度，取消后保留已下载文件，再次下载跳过缓存。整课缓存供所有句子共用，不重复存储数千段音频。
- 离线网页、MP3 Range 请求、深浅色模式、手机横竖屏布局；固定复用一个播放器，避免为每个句子新建媒体元素。
- Safari 播放在点击／滑动回调里直接请求有声播放，不先静音再异步解除静音；通过媒体事件和实际播放位置共同确认定位，兼容首次 seek 被忽略或缺少 `seeked` 通知。加载／定位和播放停滞均有 25 秒超时，权限拒绝单独提示继续授权，停止／换课取消旧回调。
- 本地校准句子时间，导出学习记录和校准 JSON，恢复收藏／掌握／校准。

只有完整缓存过的课程可以离线播放。首次打开要等待网页缓存初始化；下载建议使用 Wi-Fi、保持网页打开。浏览器可能回收存储，手机后台也可能中断下载。重新下载会补齐缓存。

## 本地运行

```bash
python3 -m http.server 8080
```

打开 `http://localhost:8080/`。离线功能需要 HTTPS 或 localhost；直接打开 HTML 不支持 Service Worker。网页资源均使用相对路径，可部署到 GitHub Pages 子路径。

## 重新构建

```bash
python3 build_content.py --source /home/lc/nce/英音
# 独立构建环境：torch==2.4.0, torchaudio==2.4.0, nltk==3.10.3,
# num2words==0.5.14；需要 ffmpeg / ffprobe，可使用 CUDA 加速。
python align_sentences.py
python publish_alignment.py
```

第一步重新导入原 LRC；最后一步必须执行，才能发布完整句子。对齐过程只下载模型和断句规则，不上传用户录音。已经生成的对齐结果可复用；改过源文件或算法后使用 `--force`。也支持 `--lesson b1-001` 和 `--limit 2`。

方法参考：[TorchAudio CTC forced alignment](https://docs.pytorch.org/audio/2.4.0/tutorials/ctc_forced_alignment_api_tutorial.html)。模型权重、Python 构建环境不提交仓库。

## 验证

```bash
python tests/test_app.py
python tests/test_safari_controls.py
# 可选：安装 Playwright WebKit 及对应系统依赖后
python tests/test_webkit_playback.py
```

需要 Python Playwright 与 Chromium。测试使用独立浏览器数据和临时服务器，覆盖真实 MP3 播放、滑动／锁定、倍速、自动区间、离线缓存及字节范围响应。浏览器自动化不等同于 iPhone Safari 真机验收。

Safari 回归测试通过受控媒体行为验证缺少事件、定位被忽略、权限错误、播放请求不返回及取消旧回调，并检查折叠选课、底栏倍速和手机布局；这些模拟不代表已完成 iPhone 真机验收。媒体许可处理参考 [WebKit 媒体播放策略](https://webkit.org/blog/7734/auto-play-policy-changes-for-macos/)。

WebKit 测试使用 iPhone 浏览器配置，覆盖原生音频首次定位、循环、大屏自动区间及源站不可达时的缓存播放。Linux WPE 的断网模拟曾返回浏览器内部错误，因而使用源站返回 503 的方式验证缓存；完整断网重载另由 Chromium 测试覆盖。它验证的是 WebKit 引擎，不是物理 iPhone；自定义浏览器路径可通过 `NCE_WEBKIT_EXECUTABLE` 指定。
