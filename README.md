# NCE · 原声英语

独立的新概念英语学习网页，交互参考 `french-2000`，使用用户提供的 `/home/lc/nce/英音` 原始 MP3 与英文 LRC。**英文与原声，以短句和长句片段为学习单位，不包含中文翻译。** 原法语项目与原始素材没有修改。

## 内容与时间轴

- 第 1 册 72 个音频课（奇数课课文，对应原文件的成对课号），第 2 册 96 课，第 3 册 60 课，第 4 册 48 课，共 **276 课**。
- 原始断句共 **4,670 个完整句子**；其中 **601 个长句**进一步拆分，共 **5,395 个学习条目**。12 秒及以上的条目由 274 个降至 9 个；没有可靠切点时保留整句。学习单位不是原 LRC 的字幕行。
- 自动检查标记 **245 个待复核条目**（含新旧边界明显变化、词置信度不足等，并非都表示切错）；其中 50 个无法可靠重定位的原句以旧时间为保守基准，不强行拆分，其中 4 个邻接边界冲突做了防重叠调整并标记。汇总见 `alignment-summary.json`，逐项原因见 `alignment-review.json`。
- 原始录音共约 **551.5 MiB**，保持原文件字节，仍为默认音源。另为每个学习条目提供六种独立合成音色，不冒充教材原声。
- 自动处理 UTF-8 / GB18030 字幕，去除软件广告和空字幕；学习句子排除课号、标题和听录音指令，保留课前问题及正文。
- NLTK 英文断句合并跨行句子，并拆分同一字幕行中的多句话。新版使用 **MMS_FA 强制对齐模型**逐词定位，置信度不足时使用英语 Wav2Vec2 模型交叉检查；无法可靠重定位的原句保留旧时间并标注待复核，不强行拆分。随后在附近的低能量停顿处寻找边界，同时保护首尾弱音；不按字符长度估算时间，不再提前 25ms 停止播放。
- 达到 24 词或 12 秒的长句，优先在标点／从句连接词处拆分，结合词间停顿和对齐置信度；每部分至少 5 词。没有可靠语意切点时保留原句，不机械切碎。片段不是独立语法句，页面显示原句编号与片段序号，并可展开完整原文。
- 发音对齐输入去除对白外层单引号，但保留 don't / I'm 等缩写；语料中已逐项检查上下文的四位年份按年份读法展开，如 1995 → nineteen ninety-five。网页显示的英文原文不变。
- `import-report.json` 保留原字幕检查结果：原 LRC 有 47 课出现越界时间戳。因此不能把原字幕时间直接当作句子时间。`alignment/` 保留旧完整句及时间，`refined-alignment/` 保存逐词证据、新片段、来源句 ID 及 SHA-256；`alignment-review.json` 列出低置信度、异常拉长词和新旧边界差异超过 0.75 秒的条目。两种模型的置信度不可直接横向比较。
- 自动对齐不等于人工听校，专名、数字、源字幕拼写问题可能影响精度。页面明确标注待复核句子，并提供本地时间校准。
- 素材目录标注“英音”，但部分 LRC 元信息写“美音”；本项目按用户提供的录音制作，没有逐课认证口音。

## 功能

- 按册、课选学，搜索课名或英文正文，收藏和掌握标记，记住最后学习位置。
- 册数采用紧凑按钮；选课列表默认折叠，展开可选课，选完自动收起，搜索／收藏筛选自动展开结果。
- 单句循环、逐句播放、整课播放及高亮、播放间隔、**0.50×–2.00×（步长 0.05）**。
- 主界面固定播放底栏也提供倍速选择，与课文上方和大屏模式实时同步，刷新后保留；切换倍速不会重播当前句。
- 大屏滑动模式：上下滑动切句，默认循环当前句；可设置课内句子区间、每句次数、自动切换及区间末尾循环。
- 大屏布局、黑白配色与按钮参考法语项目：顶部切课／锁定／退出，折叠的播放设置与字号／离线设置，进度条，底部倍速／音色／暂停／上下文。NCE 没有中文详解，使用真实的完整原文和上下文，不生成虚构译文。
- 每个条目提供三种英音（Ryan、Sonia、Libby）和三种美音（Guy、Jenny、Aria）；支持固定音色、英音交替、美音交替、六音色交替。主界面与大屏音色同步，整课播放仍使用教材原录音。六音色是预生成的本地 AAC 文件，不依赖手机系统是否安装相应声音。
- 防误触锁定，英文原文隐藏／揭示，上下文展开，80%–160% 字号，首次进入 1.5 秒手势提示。
- 按课编号区间下载原声音频，显示体积与进度，取消后保留已下载文件，再次下载跳过缓存。整课缓存供所有句子共用，不重复存储数千段音频。
- 大屏中可按本课条目区间下载三英音、三美音或全部六音色，支持取消与续传；英文和上下文字号可以分别调整、一键重置。
- 离线网页、MP3 Range 请求、深浅色模式、手机横竖屏布局；固定复用一个播放器，避免为每个句子新建媒体元素。
- Safari 播放在点击／滑动回调里直接请求有声播放，不先静音再异步解除静音；通过媒体事件和实际播放位置共同确认定位，兼容首次 seek 被忽略或缺少 `seeked` 通知。加载／定位和播放停滞均有 25 秒超时，权限拒绝单独提示继续授权，停止／换课取消旧回调。
- 本地校准句子时间，导出学习记录和校准 JSON，恢复收藏／掌握／校准。
- 拆分不重排原句 ID：旧收藏／掌握记录迁移到所有对应片段，旧学习位置迁移到原句的第一个片段。未拆句的手动校准继续生效；已拆句的旧整句校准仅保留在备份中，不套用到片段，可逐片段重新校准。旧导出文件同样支持恢复。

原声离线播放需要缓存对应整课；合成音色需要缓存对应条目和音色，下载原声不会自动下载六音色。首次打开要等待网页缓存初始化；下载建议使用 Wi-Fi、保持网页打开。浏览器可能回收存储，手机后台也可能中断下载。重新下载会补齐缓存。

## 本地运行

```bash
python3 -m http.server 8080
```

打开 `http://localhost:8080/`。离线功能需要 HTTPS 或 localhost；直接打开 HTML 不支持 Service Worker。网页资源均使用相对路径，可部署到 GitHub Pages 子路径。

## 重新构建

```bash
python3 build_content.py --source /home/lc/nce/英音
# 独立构建环境：torch==2.4.0, torchaudio==2.4.0, nltk==3.10.3,
# num2words==0.5.14；需要 ffmpeg / ffprobe，可使用 CUDA 加速。
python align_sentences.py
python publish_alignment.py
# 在完整句之上逐词重对齐、拆分长句（首次下载 MMS_FA，约 1.18 GiB）
python refine_alignment.py
# 检查 refined-alignment/ 后发布；缓存会复用，不重复推理
python refine_alignment.py --publish
```

第一步重新导入原 LRC；`publish_alignment.py` 发布完整句，`refine_alignment.py --publish` 发布新版片段。已有完整句时可直接运行 refine，无需重新导入。对齐过程只下载模型和断句规则，不上传用户录音。生成结果可复用；改过算法后使用 `--force`。refine 支持 `--lesson b1-001` 试跑，但发布必须包含全部课程。原始 MP3 字节不变，已有离线音频缓存继续复用。

方法参考：[TorchAudio CTC forced alignment](https://docs.pytorch.org/audio/2.4.0/tutorials/ctc_forced_alignment_api_tutorial.html)。模型权重、Python 构建环境不提交仓库。

### 六音色构建

需要 `edge-tts` 和 `ffmpeg` / `ffprobe`：

```bash
python build_voices.py --workers 6 --batch-size 24
python tests/test_voice_assets.py
```

仅将英文文本发送给语音服务，不上传教材录音或学习记录。批量合成使用服务返回的逐词时间标记，必须与全部输入文本精确对应、且条目边界不穿过词组；不匹配时退回逐条合成，不按文本长度猜测切点。首尾只收紧多余静音，保留短保护边界；内部自然停顿保留。

5,395 个条目去重为 5,289 个文本，六种音色共 31,734 个文件；相同文本共用资产。AAC-LC 单声道 24 kHz / 24 kbps，适配 Safari。`audio/tts/` 为音频，`voice-index.json` 为完整清单；`.voice-build/` 保存本地断点和临时文件，不提交。完整构建后才发布可用清单，`--catalog-only --preview` 仅供本地调试，不能部署。原句文本变更后需重新生成清单，不能沿用旧的完整性标志。

## 验证

```bash
python tests/test_app.py
python tests/test_safari_controls.py
python tests/test_segment_progress.py
python tests/test_voice_assets.py
python tests/test_six_voices.py
# 使用上面的声学对齐 Python 环境
python tests/test_alignment.py
# 可选：安装 Playwright WebKit 及对应系统依赖后
python tests/test_webkit_playback.py
```

需要 Python Playwright 与 Chromium。测试使用独立浏览器数据和临时服务器，覆盖真实 MP3 播放、滑动／锁定、倍速、自动区间、离线缓存及字节范围响应。浏览器自动化不等同于 iPhone Safari 真机验收。

`test_voice_assets.py` 独立检查全部条目与六音色覆盖、文件大小、AAC 容器完整性、抽样解码参数及站点总大小；`test_six_voices.py` 使用前两课的真实六音色测试界面、交替播放、离线下载和 AAC Range 响应，不替代全量覆盖检查。可用 `NCE_TEST_ENGINE=webkit` 切换测试引擎；Linux WebKit 需要 GStreamer AAC 解码器。

Safari 回归测试通过受控媒体行为验证缺少事件、定位被忽略、权限错误、播放请求不返回及取消旧回调，并检查折叠选课、底栏倍速和手机布局；这些模拟不代表已完成 iPhone 真机验收。媒体许可处理参考 [WebKit 媒体播放策略](https://webkit.org/blog/7734/auto-play-policy-changes-for-macos/)。

WebKit 测试使用 iPhone 浏览器配置，覆盖原生音频首次定位、循环、大屏自动区间及源站不可达时的缓存播放。Linux WPE 的断网模拟曾返回浏览器内部错误，因而使用源站返回 503 的方式验证缓存；完整断网重载另由 Chromium 测试覆盖。它验证的是 WebKit 引擎，不是物理 iPhone；自定义浏览器路径可通过 `NCE_WEBKIT_EXECUTABLE` 指定。
